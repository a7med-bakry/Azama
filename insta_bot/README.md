# InstaFlow — Instagram account & task manager

واجهة عربية RTL + سيرفر Python/FastAPI يستخدم `instagrapi`، مع سيشن مشفّرة وطابور مهام دائم. يمكن نشر الواجهة على Vercel والسيرفر على VPS وربطه بـ Supabase.

## المتاح في النسخة الأولى

- لوحة خاصة بمفتاح إدارة: إضافة الحسابات، حذفها، وإعادة تسجيل الدخول.
- تسجيل الدخول **باسم المستخدم أو الإيميل وكلمة المرور**. قبول الإيميل يعتمد على إنستجرام؛ إذا رفضه استخدم اسم المستخدم. بعد الدخول، يستخدم السيرفر رقم المستخدم الفعلي لتوحيد السيشن عند الدخول بالاسم والإيميل لنفس الحساب.
- استقبال تحديات كود الإيميل/الهاتف التي تدعمها المكتبة، وكود تطبيق المصادقة الثنائية. لكل خطوة تحقق معرّف منفصل يمنع قبول كود خطوة قديمة.
- حفظ إعدادات الجهاز والسيشن مشفّرة بـ Fernet. كلمة المرور تستخدم في الذاكرة أثناء الدخول فقط، ولا تُحفظ في قاعدة البيانات.
- لايكات وتعليقات للمنشورات والريلز، مع اختيار الحسابات، العدد، والنتيجة لكل حساب.
- عملية واحدة لكل حساب في الطلب؛ العدد لا يتجاوز عدد الحسابات المختارة. تُستخدم أول حسابات بعدد العمليات المطلوبة.
- إلغاء الطلبات المتبقية. العملية التي بدأت بالفعل قد تكتمل وتُسجل نتيجتها.
- تخزين SQLite محليًا أو Supabase في النشر. مفتاح Supabase الخاص موجود في Python فقط.

**مشاهدات الريلز غير مفعّلة.** طلب من المكتبة لا يثبت أن إنستجرام احتسب مشاهدة؛ يلزم اختبار مستقل قبل تنفيذها. لا توجد أرقام نجاح تجريبية في واجهة الإنتاج.

`instagrapi` مكتبة غير رسمية؛ نجاح التشغيل مرتبط باستجابة إنستجرام. الفيديو سيلفي، تغيير كلمة المرور، أو تحقق غير مدعوم يُستكمل من تطبيق إنستجرام. دعم أكواد المكتبة لا يضمن نجاح كل تحديات الحسابات. قد تنتهي السيشن؛ استخدم «دخول جديد» عند الحاجة.

## تشغيل محلي

نفّذ أوامر التشغيل والاختبارات وDocker من مجلد `insta_bot` داخل مستودع `a7med-bakry/Azama`:

```bash
cd insta_bot
```

يتطلب Python 3.9+؛ صورة Docker تستخدم Python 3.11. لا تحتاج الواجهة Node أو خطوة build.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/python scripts/init_env.py
.venv/bin/python -m uvicorn backend.main:create_app --factory --host 0.0.0.0 --port 8000 --workers 1
```

افتح `http://localhost:8000`، واضغط «إعداد الاتصال»، وأدخل العنوان نفسه وقيمة `ADMIN_TOKEN` من ملف `.env` الخاص. لا تشارك هذا المفتاح: يعطي صلاحية إدارة كل الحسابات. المفتاح يبقى في ذاكرة الصفحة ويُمسح عند قطع الاتصال أو إعادة التحميل. المتصفح يحفظ عنوان السيرفر فقط.

- احتفظ بـ `SESSION_ENCRYPTION_KEY` في نسخة آمنة: تغييره يجعل السيشن القديمة غير قابلة للقراءة.
- `.env` و`data/` مستبعدان من Git وDocker build. لا تضع فيهما بيانات قبل ضبط صلاحيات السيرفر.
- ملف `requirements.txt` يحتوي المتطلبات المباشرة؛ `requirements.lock` يحتوي الإصدارات المحلولة المختبرة. أعد اختبار المشروع بعد تحديثها.
- `GET /health` يفحص الاتصال بقاعدة البيانات، ولا يثبت جاهزية حساب إنستجرام.

## ربط Supabase

1. أنشئ مشروع Supabase وشغّل `backend/supabase.sql` من SQL Editor.
2. في `.env` على **سيرفر Python**، ضع `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` من إعدادات مشروعك. لا تنسخ المفتاح للواجهة أو Vercel.
3. أعد تشغيل السيرفر. عند ترك المتغيرين فارغين يستخدم SQLite؛ عند ضبطهما يستخدم Supabase، وفشل اتصالها لا يحوّله لتخزين محلي.

جدول `insta_records` يخزن الحسابات والمهام. RLS مفعّل ولا توجد سياسات للمستخدم العام؛ الوصول عبر السيرفر بـ service role فقط. تغيير نوع التخزين لا ينقل البيانات القديمة تلقائيًا.

## نشر الواجهة على Vercel

- استورد المستودع واختر **Root Directory: `insta_bot/web`** و **Framework: Other**.
- لا يوجد Build Command. Output Directory هو `.`؛ ملف `web/vercel.json` يضيف ترويسات الحماية.
- في السيرفر، اضبط `ALLOWED_ORIGINS=https://your-project.vercel.app` بدون `/` في النهاية. يمكن إضافة نطاقات دقيقة بفاصلة، ولا تستخدم `*`.
- من الواجهة المنشورة، أدخل عنوان API على HTTPS ومفتاح الإدارة.

## نشر Python على VPS

شغّل **عملية واحدة ونسخة سيرفر واحدة**؛ أقفال الحسابات ومحاولات الدخول في الذاكرة. لا تستخدم عدة Uvicorn workers أو replicas. قاعدة البيانات تحفظ الطابور؛ محاولة التحقق المعلقة تنتهي عند إعادة التشغيل.

```bash
docker build -t instaflow .
docker run -d --name instaflow --restart unless-stopped \
  --env-file .env -p 127.0.0.1:8000:8000 \
  -v instaflow-data:/app/data instaflow
```

ضع reverse proxy أمام المنفذ المحلي بشهادة HTTPS، ووجّه نطاق API إليه. إذا استخدمت SQLite احتفظ بوحدة `instaflow-data` ونسختها الاحتياطية. عند استخدام Supabase تظل السيشن مشفّرة بمفتاح السيرفر.

شغّل السيرفر على خدمة تدعم العمليات المستمرة؛ Vercel يستضيف الواجهة. مفتاح الإدارة هنا مناسب للوحة خاصة لمشغّل واحد؛ النسخة الحالية لا تتضمن حسابات عملاء أو عزلًا بين مستخدمين متعددين.

## سلوك الطابور

- العامل ينفذ طلبًا واحدًا في كل مرة، وبين حساباته `ACTION_DELAY_SECONDS` (افتراضيًا 10 ثوانٍ).
- لكل حساب قفل يمنع استخدام السيشن في تسجيل الدخول والتنفيذ في الوقت نفسه.
- النجاح يُسجل بعد إقرار عملية إنستجرام. الفشل أو انقطاع الشبكة قد يكون نتيجته غير معروفة، لذلك **لا توجد إعادة محاولة تلقائية للتفاعل**؛ راجع المنشور قبل إنشاء طلب جديد.
- عند إعادة التشغيل، الطلبات التي كانت `running` تصبح `interrupted` ولا تُعاد؛ الطلبات `queued` تكمل.
- الإلغاء يمنع العمليات المتبقية؛ لا يحذف لايكًا أو تعليقًا تم بالفعل.
- إذا احتاج حساب العامل إلى كود جديد، تفشل العملية وتُراجع من مسار تسجيل الدخول. العامل لا ينتظر كودًا في وسط الطابور.
- مهلة محاولة الدخول خمس دقائق، وبحد أقصى أربع محاولات متزامنة. إلغاء محاولة جارية لا يوقف طلب شبكة بدأ بالفعل؛ يمنع إكمالها عند رجوع التحكم للسيرفر.
- الواجهة تعرض آخر 50 طلبًا. سجل المهام يبقى في قاعدة البيانات.

## التحقق

```bash
.venv/bin/python -m pytest -q
.venv/bin/pip check
node --check web/assets/app.js
```

الاختبارات تستخدم عميل Instagram وهميًا: تسجيل الدخول، الإيميل، 2FA، صلاحيات API، تشفير السيشن، رفض الروابط والطلبات غير الصحيحة، الإلغاء، ونتائج العامل واستعادة الطابور. اختبارات Supabase تفحص عقد REST بمحاكاة النقل؛ لا تثبت تشغيل SQL أو RLS على مشروع Supabase حقيقي.

التجربة الحقيقية تتطلب حسابًا تجريبيًا ومشروع Supabase. لا تدخل بيانات حسابك في رسائل المهمة؛ أدخلها في الواجهة بعد إعداد الاتصال الآمن.

## الملفات

- `backend/main.py`: API ودورة تشغيل العامل.
- `backend/login.py`: محاولات الدخول والكود.
- `backend/jobs.py`: تنفيذ الطابور والإلغاء.
- `backend/storage.py`: SQLite وSupabase REST.
- `backend/supabase.sql`: قاعدة البيانات وصلاحياتها.
- `web/`: الواجهة الجاهزة للنشر على Vercel.
- `.env.example`: متغيرات التشغيل بدون قيم سرية.

المشروع موجود في مجلد `insta_bot/` داخل مستودع [a7med-bakry/Azama](https://github.com/a7med-bakry/Azama). تطبيق إدارة الوكالة موجود في جذر المستودع. نشر الواجهة والسيرفر وضبط Supabase خطوات منفصلة موضّحة أعلاه.
